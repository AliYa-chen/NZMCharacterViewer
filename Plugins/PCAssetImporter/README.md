# PC source asset importer

The Editor module converts the repository's validated CUE4Parse ActorX snapshot directly to editable `SkeletalMesh` and independent `Skeleton` assets. It only writes packages below `/Game/PCAssets/`. It never assigns an existing viewer skeleton or changes the viewer Catalog.

Python after building the Editor target:

```python
result = unreal.PCAssetImportLibrary.import_actorx(
    "/absolute/path/to/source.psk",
    "/Game/PCAssets/Characters/Example/SK_Example",
    json.dumps({"source_package": "/Game/Avatar/Example",
                "source_sha256": "<expected SHA256>",
                "slot_names": ["Body", "Hair", None]}))
verification = unreal.PCAssetImportLibrary.verify_actorx(
    "/absolute/path/to/source.psk",
    "/Game/PCAssets/Characters/Example/SK_Example")
```

Both methods return a JSON string with `status` equal to `passed` or `failed`. A new import also returns `operation=imported_and_saved`; an identical existing import returns `verified_existing`. The methods refuse to overwrite another tool's assets, reuse an unrelated Skeleton, or silently discard unsupported ActorX chunks. A changed source requires a new target package. The options' `slot_names` array must match the original section count; a null entry retains the ActorX writer's fallback name and can keep its material interface null.

Supported chunks are `PNTS0000`, 32-bit-point `VTXW0000`, `FACE0000`, `FACE3200`, `MATT0000`, `VTXNORMS`, `RAWWEIGHTS`, `REFSKELT`, `VERTEXCOLOR`, and contiguous `EXTRAUVS0` through `EXTRAUVS6`. All 309 published meshes use a subset of these chunks. The importer reverses the fixed upstream writer's Y reflection, first-two-corner swap, quaternion-Y reflection and root-quaternion-W sign change. Vertex color bytes use the writer's RGBA order.

The conversion rules were checked against the [fixed upstream ActorX writer](https://github.com/FabianFG/CUE4Parse/blob/e76778c10ed25860e11ec488750753224d067d87/CUE4Parse-Conversion/Writers/ActorX/ActorXMesh.cs) and its [color serialization](https://github.com/FabianFG/CUE4Parse/blob/e76778c10ed25860e11ec488750753224d067d87/CUE4Parse/UE4/Objects/Core/Math/FColor.cs). No upstream source code is bundled in the plugin.

Every source nonzero weight is required to survive, with a limit of eight influences per vertex and a maximum absolute error of `4/65535` for Unreal's 16-bit quantization/normalization. Verification compares saved source positions, triangle winding and material indices, all UV channels, normals, colors, bind bones, plus every built nonzero skin influence and mapped vertex position. It checks the built triangle count. ActorX has no bone-scale or tangent-vector channel: the upstream writer bakes inherited scale into bone translations; MikkTSpace tangents are generated during import. These limitations are saved as asset metadata.

The `PCAssetData` runtime module also exposes `PCSourceRecord`, an editable `DataAsset` for retaining JSON evidence and soft references to converted assets. Each record returns `IsEditorOnly=true` so evidence archives are excluded from cooked builds. A record containing original material, particle or animation JSON is source evidence, and does not execute or reconstruct the original shader, Niagara system, animation or cloth simulation. The runtime module has no Editor dependencies.

For actual target-RHI shader validation, call `unreal.PCAssetImportLibrary.verify_material_shaders(material_packages)` in a process with real Metal rendering enabled. It accepts package paths only below `/Game/PCAssets/Materials/` and returns a JSON report with the RHI, shader platform/format, feature level, per-material compiler errors and shader-map status. It waits for existing cached compilation and requests missing shaders without regenerating shader IDs or saving assets. A shader map must be present, compiled successfully, finalized, complete for the resource, valid for rendering and built for the active platform; Engine default-material fallback cannot pass. Instances sharing their parent's resource report that sharing explicitly. NullRHI returns `status=not_verified` and `success=false`. Passing this check does not establish original shader equivalence, rendered appearance, PSO execution or device performance.

Use `unreal.PCAssetImportLibrary.set_source_record_references(record, asset_packages)` to assign `PCSourceRecord.imported_assets` without loading the dependency assets. It accepts unique package paths below `/Game/PCAssets/` only after their package files exist, validates the entire list before editing the record, and returns a bool. An empty list clears the references. The caller owns saving the record.

New mesh imports use canonical triangle-corner wedges (`corner_layout_version=2`), because this UE version's legacy Mikk callback writes tangent arrays by triangle-corner order while its render builder reads wedge indices. Source points, bones, weights, normals, UVs, colors, triangles and material indices remain unchanged; corner wedges are copied so both indexing conventions agree. The tangent/normal weld tolerance is `0.00002`, matching the exported source build setting; position and UV weld thresholds remain zero. Verification also compares built normals to normalized source normals and checks finite normalized tangent frames orthogonal to those normals. A zero/invalid tangent is only recorded as a degenerate exception when every incident built triangle has degenerate UVs or geometry.

Tangent generation now uses the public `FStaticMeshOperations::ComputeMikktTangents(MeshDescription, false)` path, which writes by the actual triangle vertex-instance IDs and explicitly initializes the ignore-degenerates flag. It reads existing source normals without rewriting them; the importer verifies this before committing the description. The skeletal render builder then imports those tangents with both normal and tangent recomputation disabled. Reports identify this method as `tangent_build_method=MeshDescriptionMikkTSpace`, count actual round-trip corner/wedge mismatches in `mesh_description_corner_wedge_mismatches`, and retain the raw Mikk zero-tangent count in `mesh_description_mikk_zero_tangents`. Zero results remain subject to the built-frame verification below and cannot pass for a vertex with stable incident geometry and UVs.

For this verification classification, stable triangle geometry requires a finite cross-product squared length at least `UE_SMALL_NUMBER` (`1e-8`), matching UE's default `FVector3f::GetSafeNormal()`/`Normalize()` safety threshold. Stable UVs require a finite absolute UV determinant greater than `1e-12`. This is a classification of safely normalizable geometric normals, not a claim about MikkTSpace's internal triangle-degeneracy threshold; the local skeletal preprocessing uses `FLT_MIN` when removing degenerate triangles is disabled. A finite invalid tangent can be excepted only when the vertex has no stable incident geometry/UV triangle. Nonfinite tangent vectors always fail. `near_degenerate_geometry_tangent_exceptions` separately counts excepted vertices touching nonzero cross products below the safe-normal threshold; `geometry_normal_squared_tolerance`, `uv_determinant_absolute_tolerance`, and `tangent_degeneracy_classification` preserve the exact rule in each JSON report. All source values and triangles remain intact, and every other frame must meet the existing `0.001` normalization/orthogonality bounds.

To rebuild an existing importer-owned mesh with identical source bytes, first back up its package, then include `"rebuild_source_corner_layout": true` in the import options. The bridge verifies the old source structure, retains the exact existing Skeleton and material interfaces/slot names, replaces only the mesh's source corner layout/build data, validates the result and saves only the mesh. The report includes before/after built vertex counts and tangent metrics. Calling ordinary verification on an old invalid tangent layout fails; it cannot receive a successful frame-verification status without rebuilding.
